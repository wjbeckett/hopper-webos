# First-grade client roadmap

## Shipping bar

This client should feel like a native TV product, not a browser page packaged as an IPK.

- D-pad spatial focus system

- Android TV-style profile selection foundation: centered "Who's watching?" layout, signed-in label, centered circular avatar grid with circular focus ring/scale, Change server / Sign out actions, and hidden top navigation during profile switching. PIN verification remains supported; visual and physical-TV checks are pending.

- Continue Watching and content rails
- Home, For You, and library Recommended screens use a shared focused-item marquee above a fixed-height, internally scrollable row band; horizontal focus changes crossfade, vertical row changes roll in the navigation direction, and logos/artwork load over color gradients

- Movies / TV / Music / Audiobooks library surfaces
- Android TV-style Library Browse sort and facet panels, including server-backed catalog facets, audiobook/video-specific sort choices, large-facet search, clear/reset, and layered remote focus/back behavior. Sort, filters and match mode persist per server/profile/library (and media-type scope) behind a "Preserve sort & filters" toggle in the filter panel, as on Android TV. Browse cards match Android (title plus year only, white check watched badge, no progress bar, square art for audiobooks), the empty states use Android's wording, and a failed first page shows Retry and Clear filters. Not yet matched: Android's empty-library probe, and shuffle via the server launcher (webOS picks a random loaded item). Series More menu rows follow Android: Shuffle Series, Shuffle Season, Favorite, Mark Episode Watched/Unwatched, Mark Series Watched/Unwatched, Mark Season Watched/Unwatched (episode entry targets the focused or next-up episode). Grounded against the live server OpenAPI (`/api/v2/docs` → openapi.json, 730 paths) and read-only probes: watched, audio/subtitle prefs bodies (server echoes `default:false` in signatures; ours omits it, matching Android), edition fields, `last_file_id`, playback-start track indexes (audio ordinal verified: `ati=1`; subtitle `-1` = off and `0..n` = ordinal into the file track list (probe-verified: stream indexes 3/4 were ignored, ordinals 0/1 took effect; the Off path now sends -1 at start instead of a post-start replan)), person detail/filmography, similar, shuffle scope kinds. Live watch state: a pub/sub (`src/core/watchState.ts`) updates every rendered MediaCard in place when Watched/Favorite changes or when playback exits (resume position) or completes (watched), so Browse, Home rails, History and detail screens reflect the new state without refetching; series-page episode toggles update the rail in place. Home and For You also re-fetch their rails ~300ms after a watch-state change (debounced, single-flight with a queued follow-up, prior rails kept if the refresh fails), and the Library Recommended screen does the same (the earlier refresh missed it: Continue Watching lives on the library rails too, so the row stayed stale until remount), mirroring Android's HomeViewModel.setWatched, which refreshes the sections on success so the server's Continue Watching/Next Up resolution shows through (a marked-watched item drops out and the surfaced replacement appears without leaving Home); when the refresh removes the focused card, focus moves to the card now in the same slot (clamped to the rail, hero follows it immediately), falling back to the first card if the whole rail is gone, and the initial landing focus no longer re-fires on rail refreshes. Realtime parity with Android's HomeRealtimeCoordinator: the app holds a `silo.events.v2` websocket (`src/api/events.ts`; `POST /events/ws-ticket` then `GET /events/ws?channels=user_state,catalog` with the ticket as a second subprotocol), subscribes to both channels, drops foreign-profile `user_state` events, and coalesces `subscribed`/`snapshot`/`user_state.changed`/`catalog` frames into a 2s-debounced rails refetch (Home, For You and Library Recommended all listen; catalogue additions surface in Recently Added without leaving the screen); reconnect uses capped backoff (1s→30s), connections are bounded by the ticket's `max_connection_seconds`, retries wait for visibility, and a 20s visible-gated poll backs the socket up. Handshake, `subscribed`/`snapshot` frames and a live `user_state.changed` (watched toggle) were verified against the test server with a raw socket probe. The Home refresh failure was then reproduced and debugged end to end in a real browser (dev app against the live server, session injected, long-press menu driven in-page): root cause was `mountedRef` in HomeScreen — `React.StrictMode` double-mounts in dev, the between-mounts cleanup set the ref false and the second mount never reset it (`useRef(true)` does not re-run), so `if (mountedRef.current) setRails(next)` skipped every refresh while the requests kept firing; the guard is gone (React drops post-unmount updates anyway). Rail rows also apply the watched change locally now (Android LocalUserStateOverlay parity): items whose `UserData.Played` is true are filtered out of Continue Watching rows on render via a bus-driven version counter, so the row updates the moment the write succeeds even if the section refetch races the server's row recompute; refetches (bus 300ms, socket signals 2s, poll 20s) reconcile. Verified in-browser after the fix: marking watched removes the entry from the row in place within ~1.5s, items added by an unwatch appear in place through the refetch clusters, and the app's events socket delivers `hello`/`subscribed` through the dev proxy. Dev proxy (`vite.config.ts`) now carries websockets (`ws: true`) and rewrites the ws handshake `Origin` to `SILO_DEV_SERVER` (the server resets proxied sockets whose Origin is not the configured origin); `eventsSocketUrl` resolves relative server URLs against `location.href` and socket construction is inside the retry path. Card long-press menus now render through a portal to `document.body`: `.home-rails` is an isolated stacking context, and the fixed scrim was trapped at the rails' z-index so the hero copy painted over the menu's top; the portal lifts the scrim into the root context above the hero and top nav. (hold OK 500ms; press releases to the card action): episode cards get Play / Mark Watched-Unwatched / Add to Favorites; MediaCard everywhere (Library Browse, Home rails, Collections, History, Calendar, Search, Person) gets Play / Mark Watched-Unwatched (except Series and Audiobook cards) / Add to Favorites, each with modal focus lock and focus return to the card; rail Up from Cast/Trailers/Related on a series page returns to the remembered episode card and Down from below the hero returns to the season pills (no row skipping). The wrapper divs that menu introduced initially stripped the episode tiles' flex sizing (each wrap became an unsized flex item with `min-width: 0`, so the tiles shrank into one another); sizing now lives on the wrapper (`flex: 0 0 clamp(220px, 18vw, 330px)`, tile `width: 100%` inside), re-verified with a rendered layout check (uniform tile widths, zero overlap, rail scrolls). Focus indication follows the Android TV grammar (`FocusModifier.kt`): scale + soft white glow, no ring — media/collection/request cards scale 1.10, focused episode tiles 1.04, non-card controls 1.06, each with a `0 0 24px rgba(255,255,255,.28)` glow over the existing shadow lift; the 2dp white focus border Android also draws is deliberately omitted on web (user preference). Focused episode tiles carry a slightly stronger glow than the card grammar (16:9 art reads dimmer at 10 ft): `0 0 26px rgba(255,255,255,.38)`. Rail tracks give the focused enlargement + glow room instead of clipping it at the scroll edge: vertical padding was raised (34/40px generic, 36/40px in the home rails) with matching more-negative margins so card positions are unchanged — overflow-y hidden on the track otherwise shears the top of the scale-up + glow on Home/Recommended rails (Continue Watching and posters). The glow now covers every focusable surface, not just cards: Back/Play/Watchlist/Options/More pills, season/library/alpha tabs, nav items, browse dropdowns and panel rows, search inputs, the profile PIN pad, calendar days, option rows and the detail facts table all get the same white glow (an override layer appended at the end of `styles.css` replaces the remaining per-control white outlines/rings). Verified on a physical TV by the user after the enlargement-clip fix. The rail also full-bleeds to both screen edges now: boundary tiles cut at the physical screen edge instead of ~50px short of it, and the end gutter rides inside the scroll as a flex-item spacer (`::after`, `flex: 0 0 6vw`, clamped 58-112px via min/max-width) instead of the rail's `padding-right`, because older TV web engines omit a scroll container's end padding from the scrollable area — that left the final tile flush at the clip line with its focus ring shaved.
